# 动画生成失败与图谱箭头修复

## 本地记录中的根因

检查了会话 `7d735b27` 的事件日志与 backend/debug.log。傅里叶变换的首步多次生成完整代码，但验证反复报 plot/formula 空间不足，最后又报 `Mobject.getBounds(): t12 ... empty Three.js bounds`。这不是单纯的模型接口不可用。

1. **公式组测量包含透明留白。** 单独的公式使用字形透明度裁剪，VGroup 内部却误用了父对象的类型，按整张纹理计尺寸；按 getBoundingBox 排列又累积透明留白。
2. **错峰动画占位对象被当成画面内容。** 已安装的 manim-web 中 AnimationGroup/LaggedStart 会创建空 Group 调度对象；getCenter 抛错，导致有可见内容的正常动画被标为 incomplete。
3. **说明替换没有继承区域位置。** `replace('explanation', [note])` 原来直接加入原点；新说明容易与中心内容重叠。
4. **任务结束误判成功。** 前端以前把没有 error 的流关闭直接当成功，即使没有 explain。主智能体可能收到错误的完成反馈。
5. **多层重试互相干扰。** 主智能体可反复重新调用同一步，绕开每次最多两轮修复的限制。舞台播放失败又自行调用 regenerate，却不消费其 render_request，可能抢占正在进行的任务。
6. **图谱节点入场缩放影响连接点测量。** ReactFlow 保存了缩小节点的 handle 坐标；动画结束没有重新测量。上游 padding 修复可以改善标签，但单独应用不足以解决箭头错位。

## 已修改

- screenBounds 按每个子对象的类型计算可见字形边界，包含 VGroup 内公式。
- 公式组超过右区宽度时按可见尺寸分行，不缩字号、不删除公式项；place 按可见边界居中，报错包含实际尺寸与可用尺寸。
- 最低 20px 的可读字号检查递归覆盖 VGroup 子对象，并按组缩放后的实际字号判断；14px 公式无法再借助外层分组绕过验证。生成规范要求核心公式使用 24–32px，内容过多时分页显示。
- 已修复当前傅里叶步骤：核心公式改为 26px，离散谱关系和求和/积分分两页显示，整组播放以保留布局变换，轴标签移出公式区。
- 命名区域的单对象 replace 先执行 place 检查，成功后替换旧对象。生成代码应 `await layout.replace(...)`；自定义组仍保留既有坐标。
- 仅跳过 AnimationGroup 所创建类型且确实空的调度对象。普通不可测对象仍失败；只有调度对象的空场景仍不能通过。
- 主、递归事件消费统一跟踪本轮、本步的新 explain，空流、旧结果及错误不能认证成功。
- 同一用户轮次的同一步生成/修改失败后，不再自动重新发起。新用户消息可重试；子智能体的两轮局部修复仍保留。
- 舞台只重播同一段代码一次，仍失败则显示错误。修复统一从对话发起，不再后台抢占生成任务。
- 提示词补充区域尺寸、轴标签留白、公式分行、短动画时长和分组变换注意事项。
- 图谱整合上游节点 padding/标签尺寸修复，同时移除会改变节点几何的入场动画。保留深色风格、节点尺寸及箭头方向。
